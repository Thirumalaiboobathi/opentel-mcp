## 2. Decisions I made

1. **`_meta` key `io.github.thirumalaiboobathi.opentel-mcp/freshness`.**
   The spec says SHOULD use reverse DNS, and this is a namespace the
   project controls. It's long, so `FRESHNESS_META_KEY` is exported and
   every example uses it.
2. **Both `maxAgeMs` and `freshUntil` given: the earlier deadline wins.**
   Both are the tool's own claims, and this can only flag stale sooner.
3. **The override replaces the tool's whole window**, both `maxAgeMs` and
   `freshUntil`, and sets `limit_source: config`. Option name:
   `staleness.tools[name].maxAgeMs`. `staleness.enabled` defaults to
   `true`, which does nothing for tools without the key.
4. **No key means no attributes at all**, rather than writing
   `verdict: unknown` on every span. The `unknown` value means "the key was
   sent but is unusable", with an `unknown_reason`. Spans from tools that
   don't opt in are byte-identical to 0.16.0.
5. **Strict timestamps.** ISO strings must have `Z` or an offset. Numbers
   must be epoch ms ≥ 1e11, which rejects epoch seconds with a warning that
   says so. Numeric strings are rejected. Strings over 64 characters aren't
   parsed.
6. **Clock-skew tolerance of 5 s:** age clamps to 0 inside it, and beyond
   it the verdict is `unknown`/`future_as_of`.
7. **If any supplied window field is malformed, the whole window is
   rejected** (`invalid_window`), rather than quietly using the other one.
8. **Metric: one counter, `mcp.tool.stale_responses`, labelled with
   `gen_ai.tool.name` only.** Its cardinality is bounded by
   `mcp.tool.calls`. It's actually tighter, since only tools whose handler
   succeeded with well-formed freshness can produce a series. I didn't add
   a fresh/checked denominator counter (follow-up).
9. **Stale responses still clear thrash state.** They're successes.
10. **Health grade:** the stale-rate bounds match the failure rates (2/5/15/30%).
    - The signal needs **10 verdicts**, not just 10 calls. That's the same
      minimum-sample rule applied to the rate's own denominator.
    - Before 10 verdicts the signal is n/a, and the tooltip says so only
      for tools that report freshness.
11. **Stale count goes in the Tool health panel, not the hero.** The hero
    sentence is about failures, and stale isn't one. Keeping it separate
    keeps the hero honest and the page uncluttered.
12. **The "Stale data" filter spans all tool calls**, not one matrix cell,
    because stale rows live in the success cell. Picking a matrix cell
    resets the filter.
13. **New `--color-stale` (orange)**, distinct from failure red and from
    the "can't tell" amber the design system reserves.
14. **The UI's peer range is unchanged** (it already includes 0.17.0); only
    the devDependency was bumped.
15. The caught error from a throwing freshness getter is **not passed to
    `diag.warn`**, since it's the tool's own object and could carry
    content. The warning text never includes input values (tested).
16. **The baseline flake** (`flush-on-exit` timing) was treated as green
    after a re-run. I didn't modify the test.

## 3. The `_meta` contract (copy this)

```js
import { FRESHNESS_META_KEY } from 'opentel-mcp';
// FRESHNESS_META_KEY === 'io.github.thirumalaiboobathi.opentel-mcp/freshness'

server.registerTool('get_quote', { inputSchema: { symbol: z.string() } }, async ({ symbol }) => {
  const quote = await fetchQuote(symbol);
  return {
    content: [{ type: 'text', text: JSON.stringify(quote) }],
    _meta: {
      [FRESHNESS_META_KEY]: {
        asOf: quote.timestamp, // REQUIRED. When the data is from.
                               //   epoch milliseconds (number), or ISO 8601 WITH Z / ±hh:mm
        maxAgeMs: 5_000,       // how long it stays fresh (finite number >= 0)
        // and/or
        // freshUntil: '2026-10-12T20:00:00Z', // absolute deadline, not before asOf
        // If both are given, the earlier deadline wins.
      },
    },
  };
});
```

Optional override, in config. It replaces the tool's window, and can't
supply `asOf`:

```js
instrumentMcpServer(server, { staleness: { tools: { get_quote: { maxAgeMs: 2_000 } } } });
```

TypeScript: `{ asOf, maxAgeMs } satisfies FreshnessMeta`.

Span attributes:

| Attribute | Values |
| --- | --- |
| `mcp.tool.freshness.verdict` | `fresh` / `stale` / `unknown` |
| `mcp.tool.freshness.data_age_ms` | integer ms |
| `mcp.tool.freshness.max_age_ms` | integer ms |
| `mcp.tool.freshness.limit_source` | `max_age_ms` / `fresh_until` / `config` |
| `mcp.tool.freshness.unknown_reason` | `invalid_as_of` / `future_as_of` / `missing_window` / `invalid_window` |

Counter: `mcp.tool.stale_responses{gen_ai.tool.name}`.

## 6. Follow-ups

- **`flush-on-exit` 1000 ms cap test is load-sensitive.** It failed once
  in a full run. Consider a wider margin or running it alone.
- **Matrix highlight while "Stale data" is active:** the failure-missed
  cell stays highlighted even though the feed shows stale rows from the
  success cell. Minor, but it could confuse.
- **Staleness is invisible above the hero.** If it should be more
  prominent, a one-line secondary stat under the hero is the obvious next
  step. I held back to keep the hero about failures.
- **Metric denominator:** consider a `mcp.tool.freshness_checks` counter
  (same single label) so backends can compute a stale rate without spans.
- **Pre-existing doc nit:** in `packages/core/src/index.d.ts`, the
  `unactionableErrors` JSDoc sits above `coverage` (it's misplaced, and
  untouched by this change). The README's Configuration table also lacks
  `unactionableErrors` and `coverage` rows.
- **Light theme** wasn't screenshotted; `--color-stale` light (`#b04a0a`)
  was chosen for contrast on white but not viewed.
- Freshness is judged when the response is sent, so data that goes stale
  between the response and the agent acting on it isn't caught (in the
  ADR's Consequences).
